## 1. 协作方式

| 项目 | 做法 |
| --- | --- |
| 角色安排 | 单人完成，但保留驾驶 / 领航的角色切换：先当驾驶员动手画原型、写文档，每 40 分钟退回"领航员"视角自查（对着作业要求逐条核、把主流程走一遍） |
| 结论确认方式 | 每次切换角色前把结论写成文档（需求分析、页面清单、配色表），下一轮以文档为准，避免只信"记忆里的版本" |
| 文件管理 | GitHub 仓库管理（作业要求第 15 条），每次修改用 Commit 记录；图片与文档都可由脚本一键重建；原型用**墨刀**在线协作，提交只读分享链接 |
| 分歧处理 | 单人没有"听谁的"问题，改成两条标准当裁判：能不能对应到作业要求 / 用户场景；两条都不满足就先不做 |

## 4. 遇到的三个问题及解决

| 问题 | 怎么发现的 | 解决方式 |
| --- | --- | --- |
| 一开始想把"失物"和"招领"做成两个独立入口 | 写用户故事时发现用户其实只关心"有没有我的东西" | 合并成一个信息流 + 顶部「全部/招领/寻物」分类，用颜色区分 |
| 详情页联系方式直接展示 | 退回"领航员"视角看详情页时觉得会泄露个人信息 | 约定"联系方式只对登录同学可见"，且信息标记为已归还后收起 |
| 发布表单字段太多，一屏放不下 | 原型走查时发现要滚动两次才能点到「发布」 | 只保留 4 个必填项，描述与图片设为选填，主按钮固定在底部 |
